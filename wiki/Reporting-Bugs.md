# Reporting Bugs

Bugs are reported on the repository's issue tracker: https://github.com/puckhead73/nhl-modding-studio/issues. Use the **Bug report** form; blank issues are turned off so that every report carries the details below. One report per issue, with a short descriptive title.

Before reporting, check [Known Limitations](Known-Limitations) and [Troubleshooting](Troubleshooting): the behaviour may be expected, or there may be a workaround.

## What the form asks for

| Field | What to put |
|---|---|
| Studio build | The release or archive name (for example `v0.2`). The in-app version can differ from the archive name, so give both if you know them. |
| Windows version | For example Windows 11 24H2. |
| Game and platform | For example NHL 21 / PS4, or Not applicable. |
| Window size and display scaling | Helps with clipping or scrolling problems. |
| How was the project started? | Fresh baseline, My files, Existing project, Not applicable or Unknown. |
| Inputs attached | Database, Dictionary, Roster save, Game assets. |
| Does it also happen in a new project? | Yes, No, Not tested or Not applicable. |
| Steps to reproduce | The page, the selected item and the actions that trigger it. |
| Expected result | What should have happened. |
| Actual result and exact error | What happened, with the complete error text pasted in. |
| Frequency | Every time, Sometimes, Once, Unknown. |
| Does restarting Studio change the result? | |
| Impact | Cosmetic, Inconvenient, Blocks a task, Crash, Incorrect or lost data. |
| Workaround | Whether you can continue, and how. |
| Save or deployment details | Only when saving, packaging, installing, deploying or restoring is involved: the action used, what changed, whether it persisted after reopening, and whether destination files were affected. |
| Attachments | Screenshots, recordings, logs or the smallest example file that reproduces the problem. |

## Tips for a useful report

- For layout bugs attach the whole Studio window.
- For wrong data or assets include the affected team, player or arena name, and its id if the screen shows one under details.
- Remove personal information from anything you attach. Game files you own are yours to share only if the licence allows; a description of the file usually suffices.
- If the problem happened in the game rather than in Studio, say which game build and emulator or console you used, because no title is yet game-verified and that evidence is exactly what the project needs.
