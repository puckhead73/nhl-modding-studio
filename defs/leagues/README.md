# League identity vocabularies

One file per **measured league-code layout**. Studio never applies a single global league enum:
`studio-domain::leagues` selects a vocabulary only when (a) the open database matches the file's
`[schema]` fingerprint (tables/fields/widths present or absent) **and** (b) the session's game id is
in `applies_to` — or, when no game id is known, exactly one fingerprint matches. Anything else
leaves codes raw and reports why.

PS4 titles (NHL 15–21) carry their own `stockleagues` table and never use the vocabulary files:
their league identities are read from that table, joined on `leagueid`. Their competition
**group** tables are a separate matter — see "Competition group tables" below.

Confidence vocabulary per entry:

- `corroborated` — the same code layout is named by a PS4 `stockleagues` table on a title whose
  team-table league distribution is identical (NHL 12–15 <-> NHL 15 PS4; Legacy <-> NHL 16 PS4).
- `candidate` — inferred from the member teams' abbreviations on the committed anchor only.

Codes without an entry are shown as raw codes. Group ids (`leaguegroup` / `conferencegroup` /
`divisiongroup`) are a separate namespace; `[[groups]]` labels are scoped to one league code and
exist only where anchored.

Evidence: L1.1-A cross-tabs ([league-identity-parity-matrix](../../docs/plans/league-identity-parity-matrix.md) section 3.2)
over the committed anchors (PS3 and Xbox 360 anchors are byte-identical per title).

## Dictionary-key evidence per target (LOC-W1, R1 F5)

gen7 entries may carry `dictionary_key` (the localization key the game's executable is believed
to bind the code to) and `key_evidence`. The value in the file is a **claim about the file's
witness**, and Studio resolves it per (game, platform) at catalog time — a vocabulary shared by
several targets never promotes its neighbours:

- `traced` — read out of an executable's static table. It is shown as `traced` only on a target
  named in the file's `[key_witness].traced_on` list (game **and** platform); every other target
  sharing the vocabulary shows the witness's `otherwise` class (`by-reference`), and a `traced`
  claim with no `[key_witness]` at all is shown as `by-reference` too. Today the only witness is
  NHL Legacy **Xbox 360** `default.xex`; NHL Legacy PS3 and Legacy Recompiled inherit that
  mapping by reference.
- `hypothesis` — the key family is present in the title's own dictionary, the binding is untraced.
- No `dictionary_key` — no key is claimed for the code (NHL 07: the league labels are not in its
  dictionary at all; their source is untraced, which is not a proof that no dictionary text can
  supply them).

None of these classes says which game screens read the key; that is runtime evidence only.

## Competition group tables (`groups/`)

One file per title whose executable carries a group table indexed by the team row's global
`leaguegroup` / `conferencegroup` / `divisiongroup` ids: `groups/<game>.toml` for NHL 12–15 and
Legacy (Xbox 360 witness, research handoff P1.2-X) and `groups/ps4-<game>.toml` for PS4 NHL 15–21
(each install's own `eboot.bin`, research handoff P1.2-PS4; P1-C, 2026-09-18). Ids are
title-specific and never transfer.

**Generated by the repository tool** `competition-groups` (`crates/studio-api/src/bin/competition_groups.rs`;
P1-C-R1): the PS4 files entirely, the gen7 files only below the marker line
`# ---- witnessed structure (generated by …) ----` (everything above it is the maintained P1.2-X
metadata). `cargo run -p studio-api --bin competition-groups -- --check` refuses drift without
writing; `-- --write` renders every file first and then replaces each through a temporary sibling.
NHL 20's witness is the real CUSA15439 database (not committed; the repository anchor is an NHL 19
base copy): pass `--fixtures <root>` (or set `NHL_STUDIO_FIXTURES`) to render and verify it; without
it the tool reports that file as skipped, never as in sync.

Two evidence layers live in each file and are kept apart:

- the **key lookup** per id (`[[groups]]`, from the executable walk): `evidence` is
  `traced-static` (array order == database usage), `inferred` (usage-only: NHL 17 ids 43–60, whose
  array stores the ECHL block before the tournament block; NHL 18 ids 74–76, absent from its array)
  or `unknown` (NHL 19–21 ids 77 / 78; `hypothesis_key` is the research's hint and is never shown as
  the name). `kind` / `leagues` (which league codes share a block) are **inferred** from how the
  witness database uses each id — majority head for a used sub-group, sibling family or tournament
  head for an unused one — and the file header says so;
- the **witnessed structure** (`[signature]`, `[[known_databases]]`, `[[pairs]]`), measured on the
  witness database: the (conference, division) arrangements each league block's stock rows carry.
  `regular` pairs are the only choosable arrangements; `exceptional` pairs (an All-Star squad
  carrying its conference id in the division slot, NHL 17's three custom rows pointing into the
  ECHL block) are recorded with their team ids, browse as they are and are never offered. The
  derivation is `studio-domain::competition_groups::witness_pairs`, shared by the tool and the
  runtime.

Selection is bound to provenance (`studio-domain::competition_groups`, `leagues::attach_competition`):
`applies_to` (game id), `source` (`stockleagues` for PS4, derived codes otherwise — the open
database's schema decides), `platforms` when present, then **title identity**: a database whose
SHA-256 is a recorded `base` / `patch` identity is verified; otherwise its structural signature
(table set, team and league capacities — unchanged by any Studio edit) must identify the claimed
title and no other baked title; a recorded `excluded` identity (the nhl20 anchor, an NHL 19 base
copy) or a structure that identifies another title is refused with the numbers, and group ids
stay raw with the reason. Row agreement is reported as compatibility information only.
